## 현재 구현 정책과 명세의 차이

- 하루 1건은 현재 일반 알림의 **선택/발송 시도** 기준이다. 실제 푸시 수락 수 기준이 아니다.
- 우선순위는 같은 처리 시점에 도래한 후보끼리 비교한다. 나중에 생성된 높은 우선순위가 이미 선택·발송한 알림을 소급 교체하지 않는다.
- `ALIMTALK_PENDING`은 대체 채널 필요 상태를 기록할 뿐 실제 알림톡을 보내지 않는다. 현재는 FCM 미설정·토큰 없음·실패도 이 상태로 모인다.
- 타임레터 안내는 예약 시각에서 30일·7일을 뺀 시각을 사용하고 최초 도래 후 24시간까지만 유효하다. 이 유효 기간은 구현 선택이며 원본 표에서 확정한 값은 아니다.
- `PUSH_SENT`는 FCM이 요청을 수락했다는 뜻이다. 기기 수신·사용자 열람 완료를 보장하지 않는다.

## Swagger와 코드 대조 및 보완

- 알림함 GET·읽음 PATCH의 작업 설명, 정수 page·고정 50건·미읽음 수·취소 제외·멱등 읽음 및 400/401/404를 명시했다.
- 서버에서 주입하는 userId는 요청 파라미터에서 숨겼다.
- 토큰 PUT의 기존 필수 token/platform은 유지하고 선택 permission/installationId, 무효 시각·사유·requiresReset 응답을 명시했다.
- 설치 권한 PUT은 필수 UUID/permission과 토큰 없이 호출 가능한 계약, showPermissionBanner를 명시했다.
- 무효 이력·읽음 시각·사유의 nullable을 명시했다.
- 관리자 테스트의 선택 data 문자열 맵, 400 오류, 공통 정책 우회와 등록 토큰 수의 의미를 명시했다.
- 생성 Swagger가 오류 응답에 성공 DTO를 붙이던 부분을 공통 오류 envelope(status/code/message/data=null)로 보정했다. DELETE/읽음 PATCH의 200 data=null도 보정했다.
- 알림 API의 JSON 응답과 page의 integer 스키마를 명시했다.

검증 대상은 로컬 코드로 생성한 `/v3/api-docs`다. 운영 서버의 배포된 Swagger나 실제 기기 수신을 검사한 것은 아니다.
